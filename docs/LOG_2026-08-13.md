# LOG 2026-08-13 — sesja: naprawa bake per pixel + workflow 2 setów LOD + UX

## Główny bug dnia: zygzak granic materiałów po bake (NAPRAWIONY)

**Objaw**: LOD1 po bake miał granice materiałów w zygzak po trójkątach
(screeny w `testout/poprawka/`), LOD0 czysty.

**Przyczyna — NIE decymacja, tylko `atlas.py`**: po unwrap tri_material był
odtwarzany głosowaniem per wierzchołek (majority z 3 rogów). Zmierzono na
`testdata/test/ball.fbx`: głosowanie przestawiało **96/960 trójkątów (10%)**
— całe rzędy przy granicach. Cienki pas (1 ring) ma WSZYSTKIE wierzchołki na
granicach, więc przeskakiwał niemal w całości. Zygzak był wypalony w samą
teksturę.

**Fakt zmierzony**: xatlas ZACHOWUJE kolejność trójkątów 1:1 (weryfikacja po
pozycjach rogów). Wpis w LOG_2026-08-12 pkt 5 ("xatlas nie zachowuje
kolejności → majority vote") był błędny i to on wprowadził buga.

**Fix**: `_carry_tri_material` w `atlas.py` — przeniesienie 1:1 z weryfikacją
kolejności + fallback mapowania po tuplach wierzchołków. ZERO głosowania.

**Twarda zasada od Marka: granice materiałów w bake per PIXEL, nigdy per
trójkąt** (pamięć: lodziarz-bake-per-pixel).

## Workflow bake — finalna architektura (pomysł Marka)

- unwrap UV + bake **ZAWSZE na oryginalnej siatce** (pełna jakość, texel 1:1)
- potem **2 sety LOD-ów**: baked chain (decymacja unwrapped mesha,
  UV zachowane — jak Blender/UE/ProOptimizer) i orig chain (oryginalne
  materiały). Maska per LOD wybiera set do wyjścia
- NIE bake'ować na zdecymowanej geometrii (pierwotny "unwrap na najgęstszym
  baked LOD" był ślepą uliczką — texel wymaga topologii źródła)

## Pozostałe bugi naprawione

1. **Raycast trafiał przeciwną stronę bryły** (ciemna plama na różowym
   pasie + żółte plamy w normalce = zepsute normalne). Trimesh w trybie
   python nie gwarantuje najbliższego hitu. Fix: trafienia > 3× cage offset
   odrzucane (`raycast_cage.py`).
2. **Backendy raycast/cameras26 rzutowały same na siebie** — API `bake()`
   dostało parametr `source` (projekcja z oryginału, materiał per texel
   z punktu trafienia). Texel ignoruje source (wymaga topologii 1:1).
3. **Miniaturki AO/Roughness/Metallic pokazywały kolorowe RGB z ORM**
   zamiast swojego kanału → wyglądało jak zepsute. Fix: kanał w grayscale.
4. **GLB materiały źródłowe nie miały ORM z map** (tylko faktory) — złoty
   metaliczny ring wyglądał matowo w podglądzie orig. Fix: packed ORM przez
   `compose_orm` w `_add_source_material`.

## "Rozmyta normalka po bake" na cube — NIE BUG, za mały atlas

`testdata/test2/cube.fbx`: materiał drewna ma UV 4..16 = **tiling 12×**
tekstury 1024 → źródło ma efektywnie ~12K px na bok ściany, atlas 1024 daje
~350 px. Przy atlasie 4096 LOD1 ≈ LOD0 (screeny
`testout/claude_fix/screens/cube_lod*`). Dodany `texel_density_hint`
w `atlas.py`: po unwrap liczy stosunek gęstości per materiał i ostrzega
("~30x mniejsza rozdzielczość niż w źródle; sugerowany atlas X px").
Podawać ROZDZIELCZOŚĆ LINIOWĄ, nie pole (mylące).

## Nowe feature'y

- **bake per LOD przełączalny NA ŻYWO w viewerze po procesie**: GLB podglądu
  (`debug/<nazwa>_variants.glb`) ma oba warianty per LOD jako dzieci
  `<Nazwa>_LODn` (`_baked`/`_orig`); pasek "bake:" z checkboxami + przycisk
  Re-export. `ball.glb` w wyjściu = zawsze czysty export wg maski
- **cache re-exportu** (`<nazwa>.lodziarz_cache.pkl`, `lodziarz/cache.py`):
  oba sety LOD-ów + materiały (tekstury jako PNG bytes, tożsamość obrazów
  zachowana — packed ORM opiera się na `roughness_tex is metallic_tex`).
  POST `/api/reexport {cache, mask}` → FBX/OBJ/GLB + manifest bez bake
- **formaty exportu wg wyboru**: FBX / GLB / OBJ (GUI checkboxy, CLI
  `--no-fbx` / `--obj`). OBJ = plik per LOD + wspólny MTL (map_Pr/map_Pm
  z kanałów ORM). Podgląd viewera zawsze w `debug/` — niezależny od formatów
- **mapy AO/R/M do wyboru**: ORM spakowane / osobno roughness / osobno
  glossiness (GUI select, CLI `--split-orm` / `--gloss`); re-export GLB
  skleja ORM z osobnych plików
- **normal DirectX domyślnie wszędzie** (wejście/wyjście/viewer); powrót GL:
  `--input-normal-gl` / `--normal-gl`. GLB dostaje normalkę w konwencji
  wyjściowej (spójnie z plikami i defaultem wyświetlania)
- **i18n**: UI angielski domyślnie, przełącznik EN/PL przy logo,
  zapamiętywany w localStorage (`lodziarz_lang`)
- **branding**: logo (panel) + maskotka (pod menu widoku) z `UI/`,
  ikona exe z maskotki (`UI/lodziarz.ico`, spec `icon=`)
- **hover na slocie mapy** = powiększony podgląd 512px
